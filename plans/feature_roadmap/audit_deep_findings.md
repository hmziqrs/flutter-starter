# Feature roadmap — deep audit findings
Independent deep audit of every spec in [`features/`](features/) against the [audit checklist](audit_checklist.md) + locked [decisions](decisions.md). This is the authoritative findings file: it supersedes the original audit pass (the prior `audit_findings.md`, since removed) that the deep audit re-checked and found over-claimed. Unqualified references to `audit_findings.md` below are to that removed original pass. Every finding below survived an adversarial second pass.
**Coverage:** all 35 feature specs audited. **Totals:** 78 raw findings → **61 distinct defects** (5 cross-cutting families + 56 feature-local). **Severity:** 4 high · ~24 medium · ~33 low. **Clean:** 4 features (connectivity, feedback, native-splash, secure-store).
> **Bottom line:** every affected feature is `Status: planned` (no shipped code is broken), but a literal implementer following four specs as-written would ship broken behavior. **Branch is NOT ready to merge as-is** until the 4 high-severity contract breaks and the D4/D5/D9 cross-doc families are reconciled; the rest are doc-accuracy fixes.

## High severity — contract breaks (would ship broken behavior)
### onboarding-gate — . The router reads a captured plain bool and stays rebuild-not-reactive (onboarding-gate.md:12,56), so the flow fresh-install → OnboardingPage.onSkip → markOnboardingComplete() → context.goNamed(home) re-evaluates the redirect against the stale captured requireOnboarding=true and bounces home→onboarding, trapping the user until relaunch. The prescribed mitigation (call markOnboardingComplete() before goNamed) cannot fix this under the captured-bool design, and the described tests (onboarding-gate.md:29) never exercise this in-session transition.
**Fix:** Drop the captured bool: have the redirect read live controller state synchronously (`ProviderScope.containerOf(context).read(settingsControllerProvider).hasCompletedOnboarding`) so markOnboardingComplete's in-memory update is visible on the same tick; OR wire a refreshListenable. Add an integration case: fresh install → tap Skip (and paywall onContinue) → assert home is reached within pumpAppFrames, no relaunch.

### crash-reporting — . The plan calls `ref.read(crashReporterProvider).recordError(...)` from `_installErrorHandlers` (crash-reporting.md:31-33), but that function takes only an AppLogger (lib/bootstrap.dart:79) and runs before createApplication/ProviderScope exist (lib/bootstrap.dart:20 vs :26). The reporter cannot be provider-read at the install site.
**Fix:** Thread the reporter as a parameter mirroring AppLogger: change the signature to `_installErrorHandlers(AppLogger logger, CrashReporter reporter)` and construct NoopCrashReporter (or the real impl on DSN) in bootstrap() before the call. Reconcile the Providers bullet (crash-reporting.md:21-26) — either drop the Riverpod-provider claim for the bootstrap path, or keep crashReporterProvider only for the widget-side DiagnosticsPage reader and note _installErrorHandlers receives the reporter as a direct parameter. Fix the Tests section (crash-reporting.md:66-68): createApplication does not install error handlers today, so the test must invoke _installErrorHandlers explicitly or drive the error via the production bootstrap() entrypoint.

### deep-linking — . _AppViewState is told to subscribe to `AppLinks().uriLinkStream` directly (deep-linking.md:18-20,27-29), so a widget calls a platform-channel plugin instead of a port; this also constructs a concrete adapter outside the three allowed root files (#4) and leaves no injection seam for the documented fake-stream tests (deep-linking.md:45). Every other plugin (connectivity, settings, notifications) is reached via a provider/port.
**Fix:** Make the inbound stream part of the port: extend AppLinkHandler (or add a DeepLinkService delegating resolution to it) to own the AppLinks instance and expose `Stream<ResolvedLink> get links` + `Future<ResolvedLink?> getInitialLink()`. Construct the real adapter in lib/app/dependencies.dart (or bootstrap.dart for the initial-link read); expose a handwritten appLinkHandlerProvider overridden at the ProviderScope in app.dart. _AppViewState then ref.watches the provider's stream and dispatches via context.goNamed/pushNamed — never names AppLinks directly. Also fix the inline Audit bullet (deep-linking.md:63) from n/a to pass.

### session — . session.md:69-70 says POST /v1/auth/refresh returns `{ accessToken, expiresAt }` and 'rotates the refresh token', but the rotated token is never returned to the client. Compare /issue at session.md:67 which returns `{ accessToken, refreshToken, expiresAt }`. The documented issue→refresh→logout cycle cannot persist the new token.
**Fix:** Align the refresh response with /issue: change session.md:69-70 to return `{ accessToken, refreshToken, expiresAt }` and note 'client must persist the returned refreshToken'. (Risks note at session.md:143 signals rotation is intended, so adding the field is correct.)

## Systemic patterns
- Self-audit over-claims a pass the spec does not substantiate. The single most common defect class. Variants: (a) ≥3-consumer threshold met by counting the wrong unit — permission KINDS instead of consumer FEATURES (permissions-media.md:78), pricing/profile empty states that structurally cannot exist (state-views.md:64), the 5 auth pages miscounted as FormScaffold consumers when they only use the helper facade (form-scaffolding.md:63), pricing listed as an async-submit consumer when it has no submit state (busy-indicators.md:64), and _showInformationDialog x10+ counted though those are single-button dialogs the new enum cannot serve (toast-dialogs.md:70); (b) shared/state primitives marked n/a-pass while applying the ≥3 widget threshold and threatening feature-local demotion (offline-cache.md:120); (c) golden/dev-gallery 'no UI' claims on specs that touch the settings golden matrix (analytics.md:89,90,120) or introduce a net-new widget with no PreviewFrame (form-scaffolding.md:69); (d) Motion-guard passes that omit the AppMotion-token-sourcing clause checklist #5 requires (pull-refresh.md:69, skeleton.md:62).
- Fix propagated to one doc but not its siblings/decisions/audit_findings cells (tracker-vs-source drift). Recurring: audit_findings.md claims a fix was 'Fixed/Reconciled' but the feature doc or decisions.md was never updated. Concrete instances: audit_findings.md:226 hedged push-notifications as a non-reader but deep-linking.md:88-91 still lists it; audit_findings.md:286 claims '/v1/ added to all six routes' but D9 still omits /v1/otp/resend and push still uses /notifications/; audit_findings Resolution #3 claims the remote-config touchpoint was reconciled but ab-experiments.md:39-42 still inverts D4 and feature-flags.md:34 still files the adapter under feature_flags/; audit_findings.md:227 SettingsStore readers cell and the D5 reader-chain cell are both incomplete. The audit tracker and the source docs must be edited in the same change.
- Route prefixes/tables drift from D9. decisions.md D9 is the authoritative route table but is out of sync with per-feature test-server contracts in four places (mfa-otp resend omitted, offline-cache PUT spurious, push un-prefixed, session D3 'verify' vs D9 'logout'). D9 should be treated as generated from the feature docs, not hand-maintained.
- Native-config (iOS Info.plist usage strings + Android <uses-permission>) lives in the Audit block but not the Risks section. Confirmed for permissions-media.md (six Risks bullets, none on native config; audit_findings.md:246 over-claims 'flags them in Risks'); the same pattern was not deeply checked for biometric or native-splash even though audit_findings.md marks #9 pass for them. checklist #9 requires Risks-section treatment.
- Broken source-file markdown links (.md extension on a .dart file). The log_redactor.md → log_redactor.dart error recurs across three features and four sites; the secure_store.md → secure-store.md hyphen error recurs in session.md. Suggests the docs were written against an assumed file layout rather than verified against the tree.
- Stale/wrong code citations. Line numbers and identifiers cited against lib/ drift from the actual source: FCircularProgress cited at :504 (actual :509), onAvatarFeedback at app_router.dart:217 (actual :231), isSubmitting flag referenced but nonexistent (actual *_PresentationStatus.submitting), interactionPolicyProvider cited as a Notifier exemplar (actual plain Provider), ForuiThemeFactory.build signature missing fontScale/interactionPolicy/responsiveFontScale and listing a non-parameter 'touch'.
- Header 'Depends on' disagrees with the body. push-notifications.md:3 lists secure-store + lifecycle-observer as hard deps the Risks section calls optional/unused; license-share-update.md:3 says 'Depends on: none' while the contract uses a type owned by permissions-media; state-restoration.md:3 declares a hard dependency the Contract and Risks call 'none'/'independent'.

## Methodology
One deep auditor per feature (high effort) independently re-scored all 13 checklist items and raised candidate findings; each finding was adversarially re-verified by an independent skeptic (refute-by-default) before inclusion. Three passes were run (two full 35-feature sweeps + 1 gap-fill for features that rate-limited out), and findings were unioned + deduplicated, then consolidated by a final synthesis agent. Raw confirmed findings are preserved in the workflow journal.
